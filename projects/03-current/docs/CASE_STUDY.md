# Case study: making lateness replayable

A paused device source can hold the minimum watermark while another advances. Removing the paused source lets windows close; resuming with old readings can then revise or reject those readings. Saving source offsets alone cannot reproduce those decisions: the idle/resume interleaving is part of the input.

Current journals events and controls under one durable admission ordinal. The Python state machine owns watermark progression, heap-scheduled window close/expiration, aggregate revisions, and bounded interval joins. SQLite supplies the admission and checkpoint/outbox transactions. The alternative of sorting all input by event time would make a pleasant batch example, but would erase the actual late-event policy and fail the product objective.

An implementation mistake found during development was putting complete state expiration sweeps after every event. Its work grew with both retained state and input count, although windows can only close/expire when a watermark advances. The implementation now performs scheduled window close/expiration on control advancement using min-heaps; accepted late modifications emit their already-closed window immediately. Property tests independently enumerate boundaries across negative timestamps, out-of-order events, repeated keys and both streams, checking both dispositions and final aggregates/joins. This regression evidence checks behavior rather than copying the runtime's heap assignment algorithm.

The harder persistence boundary is publication: crashing after stage but before commit must not expose local results from an uncommitted checkpoint. The subprocess fault suite exits at four actual transaction phases and reopens the database, observing only the previous or complete new prefix. Another test loses admission acknowledgement after commit and proves its retry returns ordinal one. The independent sink test commits revision two before retrying revision one, then rejects conflicting revision-one payload reuse.

Actual CI benchmark values live in artifacts with their tested source identity. They establish local reproducibility under the specified synthetic inputs and SQLite FULL durability, not deployment capacity. The core coverage scope and exact test count are in AGENT_STATUS. Process termination does not model power failure or dishonest storage.

Limits include a single state owner, fixed topology, explicit registered inputs, retained ingress/delivery history, finite disk budgets, and key-local join scans. The next justified improvement would profile canonical serialization and join cardinality under the measured standard workload, then compare a bounded indexed join representation while preserving the same oracle and durability contract. Distributed coordination and arbitrary HTTP exactly-once effects remain outside scope.
