# Benchmarks

`benchmark --profile ci|standard --output FRESH_PATH --seed 1729` writes `benchmark.json`. CI runs 10,000 generated events per measured repetition across four partitions; standard uses 1,000,000 events, 10,000 key choices, approximately 256-byte envelopes, 10% delayed timestamps, explicit idle/resume, 30-second windows, 10-second allowed lateness, 5-second inclusive joins, four keyed workers and checkpoints every 10,000 journal records. Both include one bounded 10,000-event warmup and a separate 50%-hot-key run. CI uses five normal measurements. Standard uses one full million-event normal measurement and one full million-event hot run: the measured initial development rate made five durable million-event repetitions exceed two hours, so this is the brief's explicit run-cost repetition exception. Result metadata records measurement_runs=1 and the reason; input sizes and independent reconciliation are unchanged. Inputs are generated locally, not downloaded.

Reports separate durable admission time from state processing/checkpoint time. They include throughput samples, checkpoint duration samples, restore time, disposition counts, buffer/state peaks, watermark lag, event-time finalization lag, main/WAL disk bytes, and process RSS high-water memory where available. End-of-input's sentinel watermark is excluded from lag measurements. Finalization lag is watermark minus window end, not an invented wall-clock latency. RSS includes native SQLite and the independent oracle, and is a process-wide high-water mark rather than a per-run allocation count. Measurements include cold SQLite databases; Python/tool imports and warmup are reported separately from steady processing. Durability is WAL/FULL, with one outstanding writer operation.

All profiles reconcile accepted/rejected/replayed accounting and compare full finalized results with the independent oracle. The source commit, dirty flag, exact source/test/manifest/lock digest, root-contract digest, lock hash, interpreter, OS, seed, generator/profile identity hash and parameters accompany results. Source digest inputs are package Python files, Python tests, pyproject.toml, uv.lock and .python-version, in sorted relative-path order with path bytes followed by content; documentation and generated results are excluded. No throughput target is asserted.

The completed development CI report is `artifacts/benchmark-ci.json`: Python 3.14.8, five runs, median 1,194.68 events/s, hot 1,008.98 events/s, 114,102,272-byte RSS high-water. Every normal run yielded 25,345 latest outputs from 9,902 on-time, 65 accepted-late and 33 rejected-late inputs and matched the independent oracle. Other workers competed for resources; this is a development baseline, not an isolated performance comparison. `platform.processor()` was empty, so CPU is explicitly unknown in this portable runner; memory_limit_bytes is null because the runner does not implement a portable container-limit probe. A supplemental local environment observation is recorded in artifacts/environment-observation.json. Final committed-snapshot and standard results are coordinator-owned evidence. Do not interpret a synthetic local run as production capacity. Hot-key interval joins inherently generate more matches; output cardinality is part of workload cost and no accepted pair is silently dropped. The single ordered coordinator and canonical serialization are expected bottlenecks; no optimization claim is made without a controlled comparison.
