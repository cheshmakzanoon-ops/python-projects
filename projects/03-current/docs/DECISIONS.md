# Decisions and persisted contracts

1. **Ordered interleaving, fixed topology.** Source offsets cannot recover whether an idle decision preceded an old event. Ordinals cover events and controls together. All input IDs and the worker count are fixed in Config and checked during restore. Dynamic rescaling and network distribution are excluded.
2. **Integer milliseconds and half-open windows.** Tumbling uses size as its step; sliding uses a positive divisor of size. Negative timestamps floor toward minus infinity. An event at window end belongs to the following window. Empty string keys and repeated timestamps are valid. Join distances include both endpoints.
3. **Explicit global late policy.** On-time means timestamp at least the current operator watermark; accepted-late means timestamp below watermark with timestamp plus lateness at least watermark; older events are rejected and reported. This deliberately stricter timestamp-based policy avoids per-operator partial acceptance ambiguity. Window expiration is strictly after end plus lateness; join expiration is strictly after record time plus interval plus lateness. End-of-input is terminal, clears prior idleness and contributes positive infinity to progress. Only another end record is permitted afterward. Filtering preserves input registration, idle/resume, end and ordered-prefix validation.
4. **Single ordered state owner.** Keyed workers prepare map/filter results, then the state owner applies them in journal order. This sacrifices aggregate CPU parallelism to make global controls and coherent barriers understandable. Mapper/predicate must be deterministic inexpensive pure functions. Set `Config.pipeline_version` to a new stable version whenever their behavior changes; code does not infer arbitrary Python callable semantics.
5. **SQLite adapter, original event-time core.** SQLite owns atomic persistence and crash recovery of bytes, not watermark/window/join algorithms. FULL synchronous WAL is used for both ingress and sink. Tests kill actual processes at transaction boundaries; they do not simulate power loss, filesystem lies, or broken storage devices.
6. **Immutable delivery and greatest revision.** Delivery identity is `(job_id, operator_id, logical_result_key, revision)`. The entire canonical payload must match on retry. Late window changes advance revision; a join pair emits revision one. The sink retains every delivery identity to detect conflicting delayed reuse, and never lets an older retry replace a newer latest row.
7. **Versioning and compatibility.** Envelope and SQLite format versions are one; checkpoint code version is `current-2`. Checkpoints embed complete Config, position, job, watermarks, idle inputs, windows including revision, retained joins, disposition counts, and metrics. Mismatched Config, explicit job identity or code version fails closed. Recovery also checks state invariants and the persisted position against the journal; it does not interpret malformed checkpoints as a valid replay prefix. Version two corrects terminal-input and filter validation; version-one checkpoints require a controlled rebuild from retained raw ingress with the original complete configuration, job identity and mapper/predicate. The default CLI replay does not preserve arbitrary application configuration. Histories violating the corrected lifecycle rules and changes to external delivery revisions need explicit reconciliation; see [operations](OPERATIONS.md). Never relabel an old checkpoint. No automatic migrations or untrusted pickle exist.
8. **Budgets stop explicitly.** Config limits aggregate/join record count; Journal limits admitted records, pending outbox rows, and SQLite main-database pages. SQLITE_FULL rolls back the current transaction. WAL and temporary database overhead can exceed the main-file page budget, so it is not a whole-filesystem quota. A deployment requiring a strict total disk ceiling must also use an OS filesystem quota. Admission history and acknowledged immutable deliveries are retained, making maximum run size an explicit operational bound.

A ContextVar, timestamp sorting, or an event-ID set cannot replace the ordered journal: sorting would change recorded lateness decisions, and repeated event IDs at distinct offsets intentionally represent distinct input.
