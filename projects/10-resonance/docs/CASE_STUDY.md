# Case study: hearing the difference between note attack and note release

A musician needs to distinguish a late attack from a sustained bend without a confident-looking chart concealing uncertain audio. This project implements an offline, inspectable pipeline instead of outsourcing transcription. Integer timestamps, bounded sample buffering and explicit gaps connect numerical evidence to a playable recording.

The original core is fixed-window YIN with FFT-accelerated correlations, adaptive spectral-flux peaks, confidence/hysteresis note decoding and monotone edit alignment. NumPy/SciPy provide kernels and independent transform references; SoundFile and mido provide file encodings. A pretrained service was rejected because it would conceal the algorithm being demonstrated and require external execution.

The first clean-pluck run produced correct decoded notes but twelve onset events for six notes. Reproduce the acoustic cause with the frozen isolated-pluck fixture: a sharply truncated decay has positive spectral leakage at release, even though total energy falls. Positive spectral flux alone therefore detects both attacks and releases. Requiring rising RMS at a flux peak removed the six release false positives. The regression test independently checks all six generator attack times and excludes release neighborhoods; it would fail the initial implementation even with perfect MIDI pitches.

The initial fixed pitch evaluation achieved 6,272/6,272 predetermined eligible frames voiced within 10 cents, p95 absolute error 0.3812 cents. The six-pluck initial note starts were within 8ms of generator parameters, against a previously fixed 60ms tolerance. These measurements apply to authored synthetic signals; noisy/polyphonic real guitar is not covered by that result. The standard challenge intentionally reports errors and pitch spread separately.

A deliberate tradeoff remains: a rising-energy onset gate may miss legato attacks with no energy increase. Pitch transitions can still segment notes, but the event detector does not claim universal articulation detection. The next justified improvement would evaluate a permitted real-guitar corpus with instrument/style annotations, then add a high-frequency-change onset feature validated against held-out attacks. Long recordings also retain trajectory records linearly; a future JSONL sink could bound output memory without changing sample timing.

Independent review found three additional boundary defects and supplied reproductions. Two contiguous MIDI-60 plucks at .30/.75 seconds with .45-second durations produced two onsets but one merged note; the regression now requires two adjacent, nonoverlapping same-pitch events and separately retains one continuous bend/vibrato event. MIDI notes shorter than half a quantization tick could serialize note-off before note-on; export now rejects any interval collapsed to zero ticks before touching an existing file. Finally, the independent checker assumed the default tempo and rejected valid 600,000-microsecond tempo files; it now validates any positive 24-bit tempo, with a known 80-to-880-tick custom-tempo fixture independently parsed by mido.
