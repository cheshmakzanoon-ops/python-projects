# Operations

Install with `uv sync --locked --python 3.14.8` (tested default). Python 3.13.16 remains a fully tested compatibility path. Run format, lint, strict types, tests and build using the commands in [verification](VERIFICATION.md). CLI help lists `ingest`, `plan`, `build`, `validate`, `query`, `snapshots`, `lineage`, `recover`, `explain`, `gc`, `demo`, `benchmark` and `clean-demo`.

A dataset path must start empty or contain the `.quarry-owned` marker. Symlinks at owned storage paths are rejected. Source files are read only. The parser hashes the exact bytes consumed and compares them with the initial file hash, followed by an EOF rehash and another rehash immediately before manifest publication. This detects concurrent rewrites, including mutate-and-restore input histories that a simple before/after comparison misses. NDJSON record size defaults to 65,536 bytes. CSV headers and complete physical records share the same total byte bound. CSV requires one complete record per physical line; multiline quoted cells are explicitly rejected. Headers must contain unique declared event columns, and every row must match their width. Offsets are row ordinals rather than byte offsets.

`plan --source FILE` stages and validates in a transaction then always rolls back. It reports each bucket/node build versus reuse decision. `build` publishes current state without new business records. `explain` returns the current manifest; `lineage` returns all accepted versions, source content hashes, offsets and column dependencies. `validate` checks a selected snapshot against manifest sizes, SHA-256, physical schemas and row counts. Pinned queries verify the same properties for the selected node before passing files to DuckDB; publication verifies every reused file. A checksum error stops the operation rather than silently returning altered historical values. Validation and queries do not repair damaged content: restore a consistent backup or recover the original immutable files. A failed input contract rolls back the complete batch and does not advance its source checkpoint.

Supply a JSON contract with `ingest --contract FILE` or `plan --contract FILE`. Fields are `{kind,nullable}` where kind is string, number, integer, boolean or json. Row quality uses optional finite minimum/maximum for value. Resource settings and row bounds must be integers; booleans and fractional values are rejected in both the Python and JSON interfaces. Dataset quality uses min_rows/max_rows and validates the entire live state via per-bucket summaries, including repeated source deliveries. Only nullable additions evolve automatically. For an incompatible change, export a pinned snapshot, create a fresh dataset with the new contract/bucket configuration, transform events explicitly, verify it independently, then change the caller's dataset path. This product does not silently rewrite format metadata.

Keep snapshots by default. `gc --retain N` explicitly retains at least the newest N snapshots and every registered reader pin; history registry and tombstones remain. `recover` removes unpublished files. It verifies the format version, every configured bucket, the complete normalized/facts/daily graph, node metadata and existing owned file paths before pruning snapshots or deleting orphans; an unsafe or missing reference stops reconciliation without deleting files. Every published snapshot, including a zero-row dataset, must contain all bucket/node entries. An empty or partial partition map is corruption, not permission to reclaim the missing entries' files. Recovery validates checksum/schema/count metadata structurally but does not compare it with file contents. Run both `recover` and `validate` after a crash. Pin tokens reside in the `pins` table. A crashed process may leave a stale pin; stop all readers before clearing a proven abandoned pin with SQLite. Never clear unknown pins during active reads.

For a backup, stop the writer, close all handles, and copy the complete owned directory after SQLite checkpointing (or use SQLite's backup API plus a consistent retained-file copy while the writer is stopped). Restore to a fresh directory, open it with Lakehouse, run recover and validate, then query known snapshots. Copying only catalog.sqlite while its WAL is live is not a safe backup.

Fault suite uses real child-process termination at after_files, before_commit and after_commit. `QUARRY_HARD_CRASH=1` makes the explicitly requested ingest fault terminate with exit 91; it has no effect on normal calls. These tests verify process-crash ordering, not every device/power-loss failure. Windows lacks the tested directory-fsync boundary and the benchmark uses Unix resource accounting; Linux is the required operations platform.

Demo output requires an empty directory and a `.quarry-demo` marker. clean-demo rejects a missing marker, symlinks, or unknown top-level entries and removes only the generated run directory. Never place private files inside generated lake or benchmark subdirectories.
