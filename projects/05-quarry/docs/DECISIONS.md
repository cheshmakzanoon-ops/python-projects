# Decisions

1. **SQLite stages before file publication.** Keeping staging identities and checkpoints in the same transaction makes failed strict batches and interrupted publication naturally rollback. Holding the single writer lock during Parquet generation deliberately trades writer throughput for simple, testable atomic visibility. A multiwriter catalog is excluded.
2. **Historical exact registry instead of latest-version deduplication.** Latest-state comparison alone misses conflicts for version 1 after version 3 has been deleted. The authoritative composite primary key survives all snapshot retention operations; storage grows with accepted history. Probabilistic filters cannot replace it.
3. **Stable key buckets instead of date directories.** A correction can move days. Keeping the key's before and after states in one bucket makes replacement remove the previous day's contribution. Global queries combine per-bucket daily contributions.
4. **Semantic fingerprints instead of latest snapshot IDs.** An unrelated catalog snapshot must not invalidate all partitions. Sorted current-state and parent digests supply input identity. Normalized files have a fixed envelope; facts additionally depend on declared typed payload fields. Quality policy is revalidated independently and does not force file rewrites. Daily conservatively follows the complete facts fingerprint, so schema-only additions still rebuild that descendant. Package Python changes and analytical engine versions conservatively invalidate all nodes.
5. **Canonical payload plus typed projections.** Original payload JSON remains available for integration imports and forensic comparison. Explicit Arrow normalized fields and DuckDB projections supply real columnar data. Nullable extension fields are materialized under the collision-free `payload__` prefix.
6. **Persistent conservative reader pins.** Selection and pin insertion form one transaction. Queries and explicit validation both hold pins. Snapshot closure closes active iterators before unregistering the pin, keeping file-read lifetime inside retention protection. A crashed reader may retain storage indefinitely. Expiring an active pin could delete files being read, so clearing abandoned pins requires explicit offline diagnosis. There is no unsafe TTL.
7. **One standard measurement plus bounded warmup.** The measured standard run processes five million originals and separate correction/delete/schema batches with complete-rebuild verification. Its warmup uses 20,000 originals/eight buckets to warm engines without duplicating a multi-gigabyte historical catalog. CI uses five measurements. Standard reports one costly measurement, its explicit 20,000-row warmup parameters and fresh-catalog/cache boundaries.
8. **Immutable contract fields.** A frozen dataclass does not freeze a caller-owned dictionary. Contract construction copies field definitions into a read-only mapping; immutable `Field` values cannot change between staging and publication. Evolution constructs a new specification. Nullable additions are supported; incompatible schema/bucket changes need explicit migration.
9. **Finite floating-point aggregate contract.** Finite inputs can sum to infinity within a bucket or across bucket totals. Publication, daily reads and validation enforce global finite `DOUBLE` results. This retains the existing physical numeric type and approximate arithmetic; it is not decimal accounting. Intermediate overflow can be rejected even if a different mathematical evaluation order would produce a finite result. A different exact numeric contract would require explicit schema/transform migration.
10. **Bounded frozen history pages.** A version-only cursor can miss a later accepted obsolete event below the cursor. Pages carry an acceptance snapshot cutoff, resolved through permanent source checkpoints, so traversal stays stable through later ingestion and materialized snapshot GC. Current column metadata is labeled separately. Default pages contain at most 1,000 entries, capped at 10,000; total historical storage remains unbounded.
11. **Two-phase reclamation.** Retention commits before unlinking; otherwise a crash could restore metadata for deleted files. A fresh writer transaction recomputes all references, including publications entering the lock gap, before reclamation. Complete manifest checks precede both phases. Recovery reconciles ownership/references; explicit validation verifies content.
12. **Focused scale correctness as separate evidence.** The later 50,000-original exercise compares independent facts and daily rebuilds after seven transitions, including namespace collisions, obsolete arrivals, retention and restart. One shared-host run is a correctness diagnostic, not an updated capacity measurement. Its actual source/root hashes remain in the retained report; historical five-million-event measurements keep their original scope and limitations.
