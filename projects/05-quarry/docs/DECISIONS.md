# Decisions

1. **SQLite stages before file publication.** Keeping staging identities and checkpoints in the same transaction makes failed strict batches and interrupted publication naturally rollback. Holding the single writer lock during Parquet generation deliberately trades writer throughput for simple, testable atomic visibility. A multiwriter catalog is excluded.
2. **Historical exact registry instead of latest-version deduplication.** Latest-state comparison alone misses conflicts for version 1 after version 3 has been deleted. The authoritative composite primary key survives all snapshot retention operations; storage grows with accepted history. Probabilistic filters cannot replace it.
3. **Stable key buckets instead of date directories.** A correction can move days. Keeping the key's before and after states in one bucket makes replacement remove the previous day's contribution. Global queries combine per-bucket daily contributions.
4. **Semantic fingerprints instead of latest snapshot IDs.** An unrelated new catalog snapshot must not invalidate all partitions. Source-state digests and parent partition digests are the logical input identities, combined with schema/config/code identity.
5. **Canonical payload plus typed projections.** Original payload JSON remains available for integration imports and forensic comparison. Explicit Arrow normalized fields and DuckDB projections supply real columnar data. Nullable extension fields are materialized under the collision-free `payload__` prefix.
6. **Persistent conservative reader pins.** A crashed reader may leave a pin that retains storage. Silently expiring an active pin could delete files being read; operations therefore require an explicit, offline diagnosis before clearing abandoned pins. There is no unsafe TTL.
7. **One standard measurement plus bounded warmup.** The measured standard run processes five million originals and separate correction/delete/schema batches with complete-rebuild verification. Its warmup uses 20,000 originals/eight buckets to warm engines without duplicating a multi-gigabyte historical catalog. CI uses five measurements. Standard reports one costly measurement, its explicit 20,000-row warmup parameters and fresh-catalog/cache boundaries.
